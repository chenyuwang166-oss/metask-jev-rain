## B. System definition (METHOD §3.4 support, §9 adapter rules, README "How a model is asked")

| Item | Disclosure |
|---|---|
| B1. Support signature | Choice + Noul + Score, all with a full distribution over the exact label set (`probs` keys == `task.labels`, sum within tolerance). Not label-only. Full-coverage row requested. Noul probabilities are two-valued (B5). |
| B2. Transport | In-process (`semif_direct` class). No network at inference; weights from a local dir (`--endpoint` / `METASK_RAIN_MODEL_PATH`) or, if omitted, from the HF hub at the pinned revision at load time. Writes nothing outside the harness output paths. API flag: no. |
| B3. Prompt | One fixed rendering of the canonical record (state verbatim, instructions, criteria/levels/options, a type-specific one-word answer instruction); instruction text folded into the single user turn because Gemma's chat template has no system role; generation prompt appended; `enable_thinking=False`. Exact text in the adapter source and in the issue. **History:** written once on 2026-10-02 before any verbalized result existed for any model; first run on frozen Qwen3.5-4B / 9B, then Gemma; not iterated against Gemma public-item results. |
| B4. Read-out | One forward pass per decision, `use_cache=False`, `logits_to_keep=1`, `attn_implementation="sdpa"` (recorded), next-token logits at the answer position. Per label: logsumexp over that label's **single-token** surface forms (noul: `yes`/` yes` vs `no`/` no`; choice: `A`/` A`/`a`/` a`; score: the digit). Multi-token forms dropped; a label with no single-token form gets log-mass −1e9 (P = 0; no public item affected); a choice item with more than 26 options is refused with an explicit error (no public item has more than 6). `probs_source` per item: `"native"` for choice and score; `"native_decision_one_bin_calibrated"` for noul under the one-bin mapping (decision native, reported probability a calibration constant) — so `summary.json` lists two `probability_sources`. `usage = {input_tokens: n, output_tokens: 0}`. |
| B5. Calibration | Per precision block in `calibration.json` (`"bf16"`, `"int8"`), the adapter applying the block of the precision it loaded. Choice `softmax(m / 4.5)`; score `softmax(m / 5.0)`; noul **one-bin histogram calibration** (Zadrozny & Elkan 2001, one bin per decision side): decision = sign of `d = logmass(yes) − logmass(no)`, reported `P(yes) = p_cal` if `d > 0` else `1 − p_cal`, `p_cal` = dev precision of the sign rule (int8 0.8919 = 33/37; bf16 0.8649 = 32/37). Plainly: two-valued, discards the magnitude of `d`, never abstains (`p_cal ≥ 0.8` asserted), reports as confidence the calibration-set precision. Argmax and sign unchanged by any of this; expected position, RPS and the noul band position depend on the parameters. `noul_alternative` (T 0.05 smooth, same decisions) kept per block for the maintainers. |
| B6. Not done | No option-order ensembling / rotation (options in record order, once); no multiple forwards; no sampling or generation; no position prior; no shrink-to-argmax; no per-item or per-family prompt variation; no retries. |
| B7. Studied and not used | Choice position prior (hurt on dev; rejected by the pre-registered rule). Score shrink-to-argmax (rejected). Noul affine/Platt map (no gain at zero abstention; rejected). Noul "snap" variant (rejected). Noul 0.9/0.1 step (superseded by the one-bin rule, which replaces the arbitrary 0.9 with the dev precision). |
| B8. Noul form set | Pre-registered per precision: use `{yes, " yes"}` vs `{no, " no"}` if sign(d) equals the full 12+12 set's on all 74 public noul items, else fall back to the full set and say so. Result 74/74 on int8 and on bf16 (0 flips, min |d| 0.25); small set used in both blocks; decisions identical to the full set. |

## E. Integrity statements (METHOD §0, §1.3 item 5, §7)

1. No item was selected, dropped, re-tiered or re-labelled by us; we used `datasets/public/{easy,original,hard}.jsonl` as shipped.
2. Our local scorer is a re-implementation of METHOD v1.5 with the equal-axis, equal-type headline amendment (tier weights 10/20/30/40, per-item chance correction, noul abstention band 0.2–0.8, 10-bin ECE as in the v1 harness; the v1.5 bin count is not published). It is not the official scorer; where it disagrees with the official one, the official one is right and our estimates move.
3. The parameter search was pre-registered on the dev half (grids and selection rule fixed before scoring the check half), separately per precision. Deviations we know of: (a) the check half was scored once per candidate rule family in the first study and once per cache in the second (A4 iii); (b) an earlier draft froze T_score 4.0 because the check half preferred it — reverted to the pre-registered 5.0; (c) the noul one-bin rule was adopted after seeing that a two-valued map scored higher on the local calibration reconstruction (A4 v); (d) the chosen configuration was scored once on all 231 items.
4. We did not look at any v1.5 sealed statistic other than what is public on benchmarkheaven.com and in this repo.
5. No composite, Speed, Cost or rank estimate appears in any shipped file or in the issue.
6. Harness self-test (upstream CLI, patched copy of `main @ bb05a33`, one RTX 4090). Frozen package, 2026-10-03 12:38 UTC (freeze run `out/20261003_freeze_203822`; int8 auto-selected: 23.1 GiB free < 27; block int8; sdpa): 231/231 ok, raw accuracy 0.853 (197/231; choice 120/139, noul 63/74, score 14/18; easy 48/48, original 70/72, hard 79/111), 0 refusals / 0 × 422; decisions identical to the frozen int8 cache on 231/231 (max |Δp| 1e-6, 0 prompt-length mismatches, parity_rc 0); noul P(yes) takes only the values 0.8919 / 0.1081, 0 abstentions; p50 0.275 s / p95 0.621 s / max 1.07 s raw; harness v1 top-label ECE 0.061 (10 equal-width bins; not the v1.5 calibration axis). That run executed the shipped `calibration.json` (SHA-256 `4682cae4d181e53abcaf67bc7a9b48b4650be95eed7ef2ca79aff658cfe64aa4`, recorded per item in `raw.runtime.calibration_sha256`) and the shipped adapter (`metask_rain.py` SHA-256 `b943989039858b8463b617b89d06fae2ec027e1cf012762fe4b1d1aef7682c65`).
